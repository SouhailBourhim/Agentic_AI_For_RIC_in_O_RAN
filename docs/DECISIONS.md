# Decisions

One line per decision: date — decision — reason. Newest at the bottom.

- 2026-10-31 — Use `uv` for Python and dependencies; commit `uv.lock`. — One tool for venv + install + run; the lock file gives every machine identical versions.
- 2026-10-31 — Python 3.12 (`.python-version`), `requires-python >= 3.11`. — CLAUDE.md asks for 3.11+; 3.12 is current and supported by gymnasium, SB3 and LangGraph. uv uses its own managed 3.12.14, not Ubuntu's 3.12.3, so system updates cannot break the project.
- 2026-10-31 — Flat layout (packages at the repo root, `[tool.uv] package = false`, pytest `pythonpath = ["."]`) instead of a `src/` layout installed as a package. — Fewer concepts to explain; we never publish this code as a library. Rejected `src/` layout: it protects against import mistakes in published libraries, which is not our risk.
- 2026-10-31 — Add dependencies per checkpoint, not up front. — Each checkpoint only pulls what it needs (e.g. torch only in M02), so every dependency has a reason we can explain.
- 2026-10-31 — Smoke test `tests/test_skeleton.py` that imports every package. — pytest exits with code 5 when it collects zero tests; a real test makes `uv run pytest` exit 0 and checks the layout.
- 2026-10-31 — No linter, CI or pre-commit for now. — Not needed yet; less to explain. Can add `ruff` later.
- 2026-10-31 — Adopt `docs/PLAN.md` as the overall plan for M01–M08. — Fixes the order, the interfaces between the simulator and testbed paths, and how each hypothesis gets checked, before any code is written.
- 2026-10-31 — Split M04, M05, M07, M08 into sub-checkpoints (M04a/b, M05a/b, M07a/b, M08a/b/c) and add a timeboxed M06 spike after M03; PROMPTS.md updated to match. — The original checkpoints were each several days of unrelated work; the spike checks what the real gNB can report and control before M04a freezes the KPI record and Backend interface.
- 2026-10-31 — The pydantic `RLObjective` schema is built in M01, not M03. — The M01 observation contains the objective and M02 samples random objectives, so the schema is needed before the verifier.
- 2026-10-31 — KPI store and emulated `a1_policy` are two tables in one SQLite file (`var/ric.db`), built in M04a. — Several processes (KPM xApp, RL runner, agent) must share them; SQLite is in the standard library and needs no server. Rejected Redis: an extra service to run and explain.
- 2026-10-31 — The RL runner is the only caller of `Backend.apply_prb_split`; the LLM-only baseline goes through it with `a1_policy.mode = direct_share`. — Keeps invariant 4 true by construction: no LLM-side code ever touches the RAN.
- 2026-10-31 — Policy observations use throughput and targets as fractions of cell capacity. — The policy is trained before the testbed capacity is known; normalising lets us recalibrate the sim without changing the policy's input.
- 2026-10-31 — Conflicting intents: the verifier checks all active objectives together and rejects the newer one if they are infeasible. — Deterministic, easy to explain and test. Rejected "newest wins" (silently drops a commitment) and fixed slice priority (arbitrary).
- 2026-10-31 — Train DDPG on CPU by default. — Small MLPs are fast on 32 threads; avoids the RTX 5070 / CUDA ≥ 12.8 PyTorch requirement and leaves the GPU to Ollama.
- 2026-10-31 — Docker Desktop with WSL integration; Ollama runs on Windows (`localhost:11434` from WSL). — Already installed and working; SCTP loaded in WSL is visible inside Docker Desktop containers.
- 2026-10-31 — Testbed uses 3 nrUE, one per slice. — Same three slices as the simulator, so the policy and verifier need no special case.
- 2026-10-31 — Cuttable if late: Hermes (→ CLI client on the same 3 tools), cloud-model comparison, analyst agent (dropped now). No cloud API key yet; the LLM client stays swappable. — Testbed control and testbed evaluation are kept as priorities.
- 2026-10-31 — M01: one simulator step = 1 s. — The RL decision period, inside the Near-RT range and close to a usual KPM reporting period. Rejected 10 ms: KPM on the testbed can't follow, and training would need 100× more steps.
- 2026-10-31 — M01: fluid queue per slice; latency = base/(1−ρ) (M/M/1 time in system) + backlog drain time, with ρ capped at 0.95. — One-line formulas whose properties the tests can check. With a 0.99 cap, latency jumped by 10× from noise alone; 0.95 bounds the first term at 20× base. Rejected a packet-level simulator (ns-3): too heavy for RL training.
- 2026-10-31 — M01: PRB shares = action / sum(action), equal split if all zero. — Simplest rule that always sums to 1. Rejected softmax: harder to explain and never gives exactly 0.
- 2026-10-31 — M01: reward = weighted throughput − 2 × shortfall on min(target, load) − 1 × clipped URLLC latency excess, all divided by capacity. — Missing a target always costs more than the PRBs earn elsewhere; targets the slice can't use are not punished; scale doesn't change with capacity.
- 2026-10-31 — M01: placeholder cell of 106 PRB / 100 Mb/s. — Usual OAI rfsim 40 MHz setup; capacity is recalibrated after M06, and the normalised observation keeps the policy usable.
- 2026-10-31 — M01: `sim` imports `RLObjective` and `SLICES` from `verifier.objective`. — The objective is shared by sim, verifier, agent and policy. Rejected a new `common/` package: not in the planned layout.
- 2026-11-01 — Every checkpoint delivers at least one visualization, shown in its learning note (CLAUDE.md note format, PLAN.md §6). — Seeing the behaviour is part of understanding it; a figure also catches modelling mistakes that tests miss.

The palette validator needs Node.js (not installed), so we rely on the palette's documented validation.
- 2026-11-01 — Notebooks with marimo (dev dependency), in `notebooks/`, run top to bottom by a test. — Plain `.py` files with readable diffs, and cells re-run in dependency order, so there is no hidden state. Rejected Jupyter: JSON files with embedded outputs, and cells can run out of order.

- 2026-11-01 — TensorBoard for RL training curves (M02); Wireshark on pcaps for testbed interfaces (M06–M07). — TensorBoard is native to stable-baselines3; Wireshark has NGAP, GTP-U and E2AP dissectors and is already on Windows.
- 2026-11-01 — `sim/scenarios.py` holds named scenarios shared by the demo, the figures and the note. — One definition, so the three never disagree.
- 2026-11-01 — Move the M06 spike right after M01, before M02. — Tests the riskiest part (OAI + FlexRIC on WSL2/Docker Desktop) first, and gives a measured rfsim capacity so the policy is trained on a calibrated simulator. Costs 1–2 days of delay on the RL work.
- 2026-11-01 — Follow OAI and FlexRIC v3.0.0 from GitHub (duranta-project) with the official Docker images (gNB/nrUE v3.0.0, FlexRIC v3.0.0, CN5G v2.2.1). — OAI moved from GitLab (now a rate-limited mirror); the official images already have the E2 agent with matching E2AP v3 / KPM v3.00, so no source build and no Ubuntu 22.04 distro are needed.
- 2026-11-01 — Simulator capacity = 75 Mb/s, measured on the rfsim testbed (one UE alone 76 Mb/s, three together 74.8 Mb/s). — The policy should be trained on what the real cell delivers. Rejected "100 % PRB ≈ 100 Mb/s": a single UE never used more than ~79 % of the PRBs, so it is not reachable.
- 2026-11-01 — Traffic levels and scenarios are fractions of the cell capacity (`DEFAULT_LOAD_FRACTION`). — Recalibrating the capacity then changes no scenario's meaning (90 % load, URLLC spike 10 → 40 %). Cell tests pin an explicit 100 Mb/s config to keep their arithmetic readable.
- 2026-11-01 — Testbed KPI mapping: per-slice throughput = Σ DRB.UEThpDl, PRB use = Σ RRU.PrbTotDl / allocated share, latency = max DRB.RlcSduDelayDl; discard the first report after a subscription; ignore RSRP/SINR. — Measured in the spike: these values match iperf3 and react to overload; the first report and the RSRP/SINR values are invalid. Max latency because the worst UE is what matters for URLLC.
- 2026-11-01 — Testbed captures use a short snap length (`tcpdump -s 128`) from M06 on. — A full-payload capture at the UPF reached 13.7 GB in a few minutes.
- 2026-11-01 — Keep the simulator buffer at 50 Mb although the gNB buffers far more (~12 s of RLC delay seen). — The latency penalty is clipped, so a deeper buffer would only lengthen recovery; revisit if the sim-to-real gap shows up in M08c.
- 2026-11-01 — M02: torch CPU build from the PyTorch CPU index (`[tool.uv.sources]`). — The GPU stays free for the Ollama LLM; actor/critic nets of [256, 256] gain nothing from a GPU, and the CUDA build is several GB.
- 2026-11-01 — M02 hyperparameters: γ 0.95, Gaussian exploration σ 0.1 (SB3 [−1, 1] scale = 0.05 in shares), 200k steps, 3 seeds, 2 torch threads each, no `VecNormalize`. — ~20-step horizon is enough for second-scale effects; Gaussian is as good as Ornstein-Uhlenbeck (TD3 paper) and simpler; 2 threads measured as fast as 4; the env already scales observations.
- 2026-11-01 — M02: extra baseline "proportional to load" next to the equal split (not one of M08's four controllers). — Checks the policy beats something smarter than equal split; it turned out worse (no headroom → latency explosion near full load).
- 2026-11-01 — M02: TD3 trained after DDPG failed the goal-conditioning criterion; criteria judged per algorithm/round. — TD3 was the fallback named in the plan; in SB3 it shares every hyperparameter with DDPG.
- 2026-11-01 — M02: output smoothing filter a_t = 0.25·actor + 0.75·a_{t−1} in `SlicePolicy`, reset per episode; no penalty on split changes. — Policies moved 13–17 % of PRBs per second; the filter cuts it to ~2 % with no reward loss. A reward penalty would also slow the response to objective changes.
- 2026-11-01 — M02 round 2 (TD3, 400k steps, training load ×1.2, objective switch probability 0.02 per step); criterion fixed before training: spike gap ≥ 0.10 on every seed, filtered. — Aimed only at goal conditioning: more contended states and the same states under different objectives. Result: FAIL (seed 2 gap 0.016).
- 2026-11-01 — M02: each round is judged on the policy variant its criteria were registered on (`CRITERION_VARIANT`: round 1 raw, round 2 filtered). — Re-judging round 1 with the filter after seeing it pass would move the goalposts.
- 2026-11-01 — M02: goal-conditioning FAIL kept on record; deployed policy chosen by a rule committed before running it, on validation episodes (seeds 2000–2149) disjoint from the test seeds: beat equal split, then highest share of validation traffic patterns with gap ≥ 0.10, ties on reward → `td3_seed2`. Re-check in M08. — Picking on the test scenario would turn the test into selection. Limitation documented in docs/learn/M02-ddpg.md.
- 2026-11-01 — M02b: the M02 goal-conditioning test (URLLC share gap ≥ 0.10) is replaced as the pass bar by an oracle-validated test; the old test is still run and reported, its FAILs stay on record. — Diagnostic: a reward-optimal controller scores 0.034–0.120 on it depending only on tie-breaking (URLLC and BE weigh the same under "maximise eMBB"), so it could fail a perfect policy and pass one that over-provisions URLLC.
- 2026-11-01 — M02b goal test v2 (`rl/goal_test.py`), fixed before any M02b training: case (scenario, A, B) is material if the oracle's advantage R_A(oracle A) − R_A(oracle B) ≥ 0.02/step; per seed, T1a policy advantage > 0 in ≥ 90 % of material cases, T1b mean clip(policy/oracle advantage, −1, 1) ≥ 0.5, T2 reward above equal split; every seed must pass. Held-out test: 4 scenarios (M02 URLLC spike, eMBB surge, BE ramp, steady overload) × 4 objectives, run once with `--final`; validation: 8 scenarios × 6 sampled objectives, reward seeds 2000–2049. — Grounded in the reward, not in one behaviour proxy; objective-blind controllers score exactly 0 (checked: 89 / 30 material cases in validation / test).
- 2026-11-01 — M02b oracle (`rl/oracle.py`): one-second greedy over 861 splits (0.025 grid), same smoothing filter as the policy, knows the next second's loads exactly. Evaluation only. — A first version that assumed persistent loads lost to a fixed split (0.3 / 0.5 / 0.2) under "protect URLLC": too weak a reference would make the test easy.
- 2026-11-01 — Reward v2: URLLC latency term log(1 + excess/bound) instead of min(1, excess/bound); v1 kept for the ablation and the record. — v1 is flat beyond 2× the bound (a −0.56 → +0.46 cliff between URLLC shares 0.60 and 0.65 after a surge): nothing leads the policy to drain a URLLC queue.
- 2026-11-01 — M02b training changes: objective relabeling of 80 % of each replay batch (`rl/relabel.py`); smoothing filter inside the training env; training traffic with surge factor ×1.5–5, load ×1.2, 50-step episodes; validation checkpoint every 25k steps keeping the best (beats equal split, then highest T1b, then reward). Mid-episode objective switches dropped. — Relabeling is valid because the objective changes only the score of a transition, not the transition; the M02 test surge (×4) had 0.0 % training coverage; the actor never trained with the deployed filter.
- 2026-11-01 — The smoothing filter now works on PRB shares (`sim.cell.smooth_split`), shared by `SlicePolicy` and the env. — One definition for training and deployment; M02 rounds 1–2 smoothed the raw actor output, so re-run numbers differ slightly from the record (e.g. td3_seed2 spike gap 0.145 → 0.142).
- 2026-11-01 — M02b protocol: dev round (full recipe + 4 leave-one-out ablations × 3 seeds, 400k steps) judged on validation only; recipe = all seeds pass validation, then highest mean T1b, else stop before the test; confirmation on 5 fresh seeds (10–14); held-out test run once; deployed = confirmation seed with highest validation T1b, then reward. — Development decisions never see the test; the final claim is on seeds and cases never used for any choice.

Rejected option 3 (KPM only on the testbed): the loop would never close on the real RAN.

- 2026-11-01 — M03: the verifier checks `merge(active intents + new)`: per slice the highest target, the tightest URLLC bound, the newest still-active intent's weights; re-verified on every change of the active set; `a1_policy` rows record all merged `intent_ids`. — What is verified is exactly what runs; rejected "newest replaces", where an accepted intent would silently drop an older guarantee.
- 2026-11-01 — M03: checks in a fixed order (schema, window, latency physics, budget, floor, training range, conflict, step), first failure returned with a sentence that has the numbers. — Same input, same decision and same reason; an operator can act on the reason.
- 2026-11-01 — M03: "feasible" uses the simulator's cell model: share = target / C, and for URLLC with bound B, target / (C (1 − base/B)) from the M/M/1 latency. - 2026-11-01 — M03: reject objectives outside the policy's training range (targets > 40 % of capacity, bound outside 5–50 ms); the constants moved to `verifier/objective.py` and `sim/env.py` imports them (same values, same random draws, checked). — A goal-conditioned policy is only trustworthy on goals like those it was trained on.
- 2026-11-01 — M03: every submitted intent must end (`valid_until` required), lasting 10 s to 24 h and starting within 1 h; weight step ≤ 0.5 and target step ≤ 30 % of capacity per slice between the merged objective before and after.
